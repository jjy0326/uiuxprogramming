# 5주차 JavaScript 기능 추가 기록

## 추가한 기능

제목 입력창에 입력한 내용으로 페이지 제목을 변경하는 기능을 추가했다.

## 수정한 내용

- JavaScript를 사용해 제목 입력값을 가져오도록 수정했다.
- 입력한 제목이 비어 있는지 확인하도록 조건문을 추가했다.
- 저장 버튼을 누르면 입력한 제목으로 h1 제목이 변경되도록 구현했다.
- 브라우저 탭의 제목도 함께 변경되도록 수정했다.
- 변경된 제목을 localStorage에 저장해 새로고침 후에도 유지되도록 구현했다.
- 초기화 버튼을 눌러 제목을 원래대로 되돌릴 수 있도록 추가했다.

## 달라진 점

제목을 입력하고 저장 버튼을 누르면 페이지의 h1 제목과 브라우저 탭 제목이 변경된다. 새로고침 후에도 변경된 제목이 유지되며, 초기화 버튼으로 원래 제목으로 되돌릴 수 있다.

## 9회차 주 입력 폼 개선 내용

### 1. 추가·수정한 기능

- 하루노트의 `newnote.html`에 새 노트 작성 폼을 구성했습니다.

- 수업 주제에서 `기타`를 선택하면 직접 입력 칸이 나타나며, 다른 주제를 선택하면 입력 칸이 숨겨집니다.
- 숨겨진 직접 입력 칸은 `disabled` 처리하여 입력 및 제출 대상에서 제외했습니다.

- 입력 내용을 미리보기로 확인하는 기능을 유지했습니다.

### 2. 입력 조건 및 안내

| 입력 항목 | 입력 조건 |
| 노트 제목 | 필수, 2~60자 |
| 수업 주제 | 필수, 선택 목록에서 선택 |
| 직접 입력할 주제 | `기타` 선택 시 필수, 2~60자 |
| 항목 제목 | 필수, 항목별 2~80자 |
| 항목 내용 | 필수, 항목별 10~1,000자 |

입력 중 제목과 항목별 글자 수를 표시합니다. 입력 조건에 맞지 않으면 해당 입력란 아래에 오류 문구와 수정 방법을 표시하고, 내용을 수정하면 오류 표시를 해제합니다.

### 3. 제출 및 결과 처리

- 폼의 `submit` 이벤트에서 입력값을 검사합니다.
- 입력 조건을 충족하지 못하면 저장을 중단하고 첫 번째 오류 항목으로 포커스를 이동합니다.
- 저장 중에는 진행 문구를 표시하고 저장 버튼을 비활성화하여 중복 제출을 방지합니다.
- 저장에 성공하면 완료 문구를 표시하고 입력 폼을 초기화합니다.
- 브라우저 저장에 실패하면 오류 문구를 표시하며 입력 내용은 유지하여 다시 시도할 수 있도록 했습니다.
- 서버 연동 없이 브라우저 `localStorage`를 사용합니다.

### 4. 수정한 파일

- `index.html`: 잘못된 닫는 태그를 정리했습니다.
- `newnote.html`: 주제 선택, 조건부 직접 입력, 입력 도움말, 글자 수 및 오류 표시 영역을 추가했습니다.
- `newnote.js`: 조건부 입력, 실시간 입력 상태, 유효성 검사, 저장 중 상태, 저장 성공·실패 처리 및 미리보기 동작을 정리했습니다.
- `script.js`: 페이지마다 존재하는 요소가 다르므로 요소가 있을 때만 이벤트를 연결하도록 수정하고, 새 노트와 기존 2주차 노트를 메인 페이지에서 표시하도록 정리했습니다.

### 5. 브라우저 확인 순서

1. 제목과 항목 내용을 비워 둔 상태에서 저장하여 필수 입력 오류가 표시되는지 확인합니다.

- 현재 화면에 해당하는 메뉴에 `is-current` 클래스를 적용합니다.
- 현재 메뉴에만 `aria-current="location"`을 적용하고 나머지 메뉴에서는 제거합니다.
- 메뉴 선택, 주소 해시 변경, 브라우저 뒤로/앞으로 이동, 스크롤 위치 변경에 맞춰 현재 메뉴와 주소를 동기화합니다.
- 스크롤에 따른 주소 변경은 `history.replaceState()`를 사용해 불필요한 방문 기록을 만들지 않습니다.

### 목록 필터와 빈 상태
- `전체`, `주제 있음`, `주제 없음` 필터를 제공합니다.
- 필터 버튼의 선택 스타일과 `aria-pressed` 값을 함께 갱신합니다.
- 전체 노트 수와 현재 표시 개수를 안내합니다.
- 저장된 노트가 없는 상태와 선택한 필터에 해당하는 노트가 없는 상태를 구분해 안내합니다.

### PC·모바일 메뉴 열기/닫기
- PC와 모바일 화면 모두 메뉴 열기/닫기 버튼을 표시합니다.
- 처음에는 메뉴 목록을 숨기고, 버튼을 누르면 펼쳐지도록 구성했습니다.
- 다시 버튼을 누르면 메뉴 목록이 닫힙니다.
- 메뉴의 열림 상태에 따라 버튼 문구와 `aria-expanded` 값을 함께 갱신합니다.
- 메뉴 항목을 선택하면 메뉴가 닫히고 해당 영역으로 이동합니다.
- PC에서는 가로형 메뉴, 모바일에서는 세로형 메뉴로 표시됩니다.

## 4. 테스트 순서
1. `index.html`을 Live Server로 실행합니다.
2. 상단 메뉴를 눌러 각 섹션으로 이동하고 메뉴 강조 상태를 확인합니다.
3. 주소창의 해시와 `aria-current="location"`이 현재 위치에 맞는지 확인합니다.
4. 메뉴를 여러 번 이동한 뒤 브라우저 뒤로/앞으로 가기를 확인합니다.
5. 페이지를 새로고침해도 현재 주소에 맞는 메뉴가 선택되는지 확인합니다.
6. `newnote.html`에서 주제가 있는 노트와 주제가 없는 노트를 저장합니다.
7. 전체/주제 있음/주제 없음 필터를 눌러 카드와 결과 개수가 바뀌는지 확인합니다.
8. 전체 노트가 없는 경우와 선택한 필터 결과가 없는 경우 안내가 구분되는지 확인합니다.
9. PC 화면에서 메뉴 열기 버튼을 눌러 메뉴가 펼쳐지고, 메뉴 닫기 버튼을 눌러 다시 숨겨지는지 확인합니다.
10. 브라우저 너비를 768px 이하로 줄여 모바일에서도 열기/닫기와 메뉴 선택 후 닫힘이 작동하는지 확인합니다.
11. `aria-expanded` 값이 열림/닫힘 상태에 맞게 변경되는지 확인합니다.
12. `week2.html`에서도 PC·모바일 메뉴 동작과 기존 탭, 노트 작성 기능을 확인합니다.
13. `newnote.html`에서 기존 노트 작성·미리보기·저장 기능이 유지되는지 확인합니다.
